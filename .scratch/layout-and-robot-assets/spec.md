# Motion Studio layout cleanup and shared robot asset ownership

Status: ready-for-agent
Category: enhancement
Date: 2026-10-29
Scope: implementation specification and local tickets; implementation has not started.

## Problem Statement

Motion Studio owns its workflows, but active implementation and tests are split
between the package, scripts, experiment directories and historical external
checkouts. Generated models, checkpoints and viewer geometry coexist with
experiment records. Documentation output depends on a particular research report.
Robot selection is repeated in integration configuration without a shared,
validated identity for source assets, model representation, pose or geometry.
Cleanup must preserve the ability to inspect and reproduce historical work,
including dirty repositories, ignored assets and machine-specific compatibility
paths. A layout change must never silently change a baseline's inputs.

## Solution

Move active reusable behavior behind small Motion Studio operations, retaining
thin command entry points and explicitly supported historical reproduction paths.
Inventory and seal evidence before any relocation. Keep experiment source,
configuration, provenance and small results together; store bulky generated bytes
in ignored output storage with verified compatibility for old readers. Build new
documentation editions separately from research evidence.

Introduce small versioned robot definitions and named poses, resolved and
validated by Motion Studio against pinned upstream asset bundles. Astro assets
continue to come from menagerie_x. Concrete adapters own backend configuration,
mapping and execution. Official UMR reproduction continues to use its original
bundled G1 assets; canonical comparison cohorts require deliberate asset selection
and have separate identities, outputs and correspondence compatibility checks.

## User Stories

1. As a workflow author, I want to request a concrete outcome through a Motion
   Studio operation, so that I do not orchestrate upstream internals in a script.
2. As a maintainer, I want upstream source and runtimes to stay independently
   pinned, so that layout work does not change numerical methods or environments.
3. As a researcher, I want historical commands, revisions, patches and results
   retained, so that new ownership boundaries do not erase experimental evidence.
4. As a workspace owner, I want tracked, untracked and ignored work inventoried
   before migration, so that a manifest pin cannot be mistaken for a backup.
5. As a baseline reviewer, I want official G1 reproduction to retain UMR's bundled
   assets and calibration, so that a shared robot catalog cannot alter its inputs.
6. As a comparison author, I want to select a robot edition and pose explicitly,
   so that matching embodiment names do not conceal different geometry.
7. As an Astro user, I want menagerie_x to remain the asset source, so that mesh,
   model and license maintenance is not duplicated in Motion Studio.
8. As an adapter author, I want validated source paths, joint order and coordinate
   conventions, so that backend conversion happens once at a concrete seam.
9. As a reviewer, I want separate URDF/MJCF consistency results and intentional
   differences, so that model conversion is not treated as byte equivalence.
10. As a correspondence user, I want geometry and pose changes to invalidate
    incompatible learned artifacts, so that stale slots cannot be reused silently.
11. As a contributor, I want one documented test command and explicit runtime
    tiers, so that scattered suites are neither missed nor run in the wrong venv.
12. As a Wendy user, I want the existing conversion outputs and timing preserved
    behind an owned adapter, so that CLI cleanup does not change the experiment.
13. As an evidence reader, I want legacy labels and measured results preserved,
    so that reconstruction is not presented as a fresh numerical run.
14. As a documentation reader, I want offline navigation and saved figures to
    survive source/output separation, so that old entry paths remain useful.
15. As a maintainer, I want README navigation to describe the actual layout,
    so that package, tests, schemas, tracker, robot definitions and outputs are found.
16. As a researcher, I want missing environments, assets and permissions reported
    explicitly, so that source availability is not claimed as runtime validation.

## Implementation Decisions

### Ownership and rollout

- Apply [development policy](../../docs/workflow.md#development-policy).
  Package code owns reusable behavior, explicit interfaces and concrete adapters;
  scripts parse arguments, wire runtime dependencies and print results. Do not
  import script implementations from package modules after their slice migrates.
- Begin with concrete functions and typed inputs/results. Keep external imports,
  path translation and runtime invocation private to adapters. Preserve the
  existing independent environments. No plugin registry, universal motion format
  or generic solver abstraction is needed.
- Migrate active workflows in complete slices: Wendy conversion, evidence
  reconstruction, documentation building and canonical comparison preparation.
  Keep frozen historical experiment scripts and pair runner usable at recorded
  revisions. Reuse their demonstrated rules without forcing a bulk rewrite.
- Use expand–migrate–verify: introduce owned implementation and compatibility,
  migrate active callers, then retire duplicate active code only after parity.
  The 400–500-line guideline is soft; split by responsibility, not line count.

### Preservation and dependencies

- Record inventory entries for Git HEAD/status, tracked edits, untracked work,
  ignored assets, worktree links, environments and compatibility paths. Hash
  selected evidence/source files and record size, path, symlink target and role.
  Store sensitive or bulky inventory payloads in ignored local storage; tracked
  records contain safe summaries and hashes. Do not copy credentials into records.
- Preserve external changes as base revision plus complete reconstructable patch
  or commits, untracked-source archive and ignored-asset manifest. Verify recovery
  in temporary scratch space without resetting or editing live checkouts.
- Register active hiphi2smplx at the inspected pin without installing/updating it.
  Historical UMR worktree/clone remain separately documented dependencies rather
  than additional default bootstraps. Do not assume old patches cover current work.
- Treat menagerie_x as an explicitly located, pinned asset source. The current
  bootstrap tool only accepts direct children of externals; do not move or clone
  menagerie_x merely to satisfy that restriction. Robot source resolution may
  accept its existing checkout through a supplied local source-root mapping.

### Storage and migration

- Experiment directories retain reproduction code, configuration, provenance,
  patch records and small reviewed results. Classify by role, not extension alone;
  a JSON viewer mesh can be bulky generated data, while a patch is essential source.
- Store new run artifacts in fresh run directories under ignored output storage.
  An ignored asset cache may hold immutable source closures; generated XML,
  geometry, checkpoints and learned artifacts belong to runs. Cache lookup is
  content-verified and never silently fetches or modifies a source checkout.
- Inventory every existing bulky artifact before relocation. Copy into a fresh
  destination, verify byte hashes and internal references, then install recorded
  legacy aliases only where safe. Existing records retain original paths/hashes;
  an additive relocation map records old path, new path, hash, kind and validation.
  Do not overwrite a conflicting destination or follow a path outside approved
  roots. Resume verifies completed copies; failures retain originals.
- Preserve old HTML/JS/JSON link behavior, file and optional HTTP reading paths,
  absolute paths where still used, and frozen asset closures. If compatibility
  cannot be proved, retain the original and record the exception. No blanket
  deletion, broad ignore rule hiding evidence, Git history rewrite or cleanup of
  unrelated local files. Inventory-backed batches complete the scoped migration.

### Documentation source and output

- Keep authored templates, catalog, styles and search source separate from
  generated reading editions. The docs builder becomes an owned operation with
  explicit evidence roots and destination. Default new editions go to a fresh
  documentation output directory, not inside the research report.
- Treat the preserved research bundle as read-only input. Copy/decorate only into
  the new edition. Preserve prior decorated pages and originals by hash. Missing
  canonical inputs fail before publication; saved-source mode remains explicit,
  hash-verified and visibly labeled.
- Preserve complete static root/basic/home entry pages and legacy anchors;
  generated compatibility aliases are a documented exception to the source tree.
  Prefer ordinary relative links over script redirects. Do not turn historical
  research pages into a dependency of the new reading entry's output location.
- Core reading requires no server or network; optional 3D inspectors remain
  separately labeled. Static checks and HTTP browser checks do not prove
  direct-file rendering; record an unavailable file-open check honestly.

### Shared robot definition and resolver contract

- Proposed small layout: `robots/g1_29dof/`, `robots/astro_p2_29dof/` and
  `robots/astro_p2_43dof_dex3_1/`, each with `robot.json` and `poses.json`.
  Owned resolution/validation lives in `motion_studio/robots`. Final schema/file
  names may change during the first slice if tests justify it; stable IDs and
  explicit contracts matter more than these names.
- Each versioned definition identifies robot/variant, upstream repository and
  exact commit, required source-relative files and SHA-256 closure (including
  referenced meshes/includes), representation and intentional modifications,
  notice/source-record references, joint names and explicit application order,
  root frame/axes, units and root quaternion convention. Provenance records both
  the committed source and any permitted local patch; default canonical resolution
  rejects mismatched required bytes. Unrelated local generated files do not
  alter selection. Unknown license coverage is recorded as unknown.
- Named poses use joint-name keyed scalar radians, with an explicit base pose
  and merge rule if a hand-only overlay is used. Resolve to a complete ordered
  vector; reject duplicate/unknown/missing joints, nonfinite/out-of-range values
  and representation mismatches. Free-root coordinates are separate from scalar
  joints; native model order and application order are related by validated names.
- Public operation accepts a definition ID, representation, named pose and local
  source roots. It returns an immutable typed selection with resolved source
  closure, ordered joints/pose, conventions, content identity and validation
  findings. It does not launch a simulator, install dependencies, fetch assets,
  create generated model files or mutate inputs. Errors identify the missing or
  incompatible requirement. Separate adapter preparation materializes writable
  copies under a fresh run and records derived-file hashes.
- Static validation uses schema/closure/joint checks without heavy imports.
  Runtime representation checks run in their owning environment: compare named
  movable joints/types, limits, axes, frames, transforms and inertial totals at
  declared poses with recorded tolerances. Compare collision and visual geometry
  separately; known refinements are explicit exceptions, unexplained differences
  fail. Mark unsupported checks unverified, never equivalent by assumption.
- Initial source defaults: Astro bundles from the inspected menagerie_x revision;
  shared G1 from the pinned UMR shipped G1 bundle, identified separately as an
  explicit comparison selection. Do not substitute the menagerie G1 model, which
  has different editions. URDF/MJCF pairs are candidates until validated; absence
  of parity blocks a comparison claiming parity, not historical reproduction.

### Cohorts, learned artifacts and adapter adoption

- Official reproduction remains `reproduce_g1_baseline` with its original pin,
  shipped assets/configuration and full run-local bundle copy. It does not accept
  a canonical asset override or consult shared definitions. Add regression checks
  at this existing seam; keep recorded historical assets and results immutable.
- New canonical comparison preparation requires explicit robot/pose/representation
  selection and a fresh run. UMR configuration translation remains in its concrete
  adapter; no caller imports upstream modules. First deliver preparation and
  validation receipts, not another generic training/solver launcher.
- Record the selection identity plus adapter/configuration/conversion versions,
  source clip/shape hashes, units/axes/order, sampling policy, centering, pose,
  seed, correspondence settings and output hashes. Include selected visual versus
  collision surface and generated topology/order in stage-specific fingerprints.
  Paths alone never establish compatibility. Different settings or bytes cause a
  cache miss or explicit rejection; no fallback to a similarly named old checkpoint.
- Any asset/geometry change creates a new comparison identity. It can require new
  sampling, correspondence training and binding even when joint names match.
  Cross-method comparisons require an explicit cohort manifest and representation
  check results; this effort does not claim equivalent algorithms or dynamics.

## Testing Decisions

Prefer observable outcome seams: existing G1 operation, owned conversion/evidence/
docs operations and robot selection/preparation. Test expected outputs and failure
behavior against independent examples or sealed records, not private helper calls.

- Establish one root check entry with explicit pure-Python, saved-evidence,
  JavaScript search and external-runtime tiers. Default checks discover all pure
  suites; inventory declares opt-in suites and prerequisites. Missing prerequisites
  produce actionable reports, not a false all-tests-passed result. Reuse unittest
  unless a demonstrated need justifies another runner; do not install a shared venv.
- Follow existing public G1 overwrite/pin/help checks and legacy seal/label tests.
  Add fixtures for required-asset drift, unsupported representation, pose limits,
  name/order mismatch, cache incompatibility, failure before mutation, run-local
  generated files and baseline immunity to canonical selection changes.
- Migration checks use an independent before/after file manifest, hash equality,
  link traversal and conflict/interruption cases. New locations and legacy aliases
  must return the same bytes. Check frozen source closures and repository status
  except declared owned changes; do not overwrite inventory to hide drift.
- Docs checks cover catalog IDs, all local links/anchors, root/basic/home entries,
  manifests, source hashes, missing-input failure and explicit saved-source labels.
  Compare old/new reader behavior and verify copied research input is unchanged.
- Representation checks use named physical quantities and explicit units/tolerances.
  Start with 1e-6 m translation and 1e-6 rad orientation/limit comparison tolerances
  for expected-equal kinematics; record and justify any change before accepting
  real source differences. Intentional geometry differences are enumerated rather
  than hidden by numerical tolerance. No check implies dynamic feasibility.
- Do not rerun GPU training for structural parity by default. Use frozen hashes,
  small preparation/runtime smoke checks and existing numerical records. A fresh
  expensive numerical reproduction requires its environment/assets and an explicit
  fresh run record; report it separately from this effort's structural acceptance.

## Out of Scope

No implementation occurs while publishing this spec/tickets. Future implementation
does not include solver/method changes, baseline advancement, bulk historical
rewrites, dependency upgrades, shared environments, new upstream patches, physical
robot validation, mechanical hand calibration, a universal motion format, a plugin
framework, asset redistribution, remote issue publication or automatic downloads.
Full cross-method retargeting and retraining are follow-up experiments, not a
condition for completing selection/preparation and preservation work here.
