# 06 — Build offline documentation editions separately from research evidence

Status: claimed
Category: enhancement
Spec: [Layout and robot assets](../spec.md)
Blocked by: 01, 02
Dependencies: [01 preservation](01-preservation-inventory.md), [02 checks](02-test-discovery.md)

## Context

The builder, verifier and search test assume outputs/umr-binding-report. Builds
decorate its original pages and generate root/basic entries plus docs/site/home.
Authoring templates are separate already, but output publication is coupled to
research evidence and fresh clones lack the ignored source bundle.

## Outcome and scope

Move reusable docs implementation behind an owned build/verify operation with
explicit source/evidence roots and fresh edition destination. Default new output
belongs under outputs/docs-site with edition isolation. Preserve existing reading
paths, bilingual legacy anchors, saved figures and optional inspectors.

## Acceptance criteria

- Build consumes the catalog, authored templates/styles/search and recorded
  evidence; no UMR imports, training, downloads or new numerical results occur.
  Research input and previously preserved originals are read-only and hash-stable.
- A fresh edition contains required copied evidence and locally bundled reading
  resources. Decorate copies only. Existing root docs.html, docs-basic.html and
  docs/site/home.html remain complete static reading entries with valid relative
  links. Preserve old entries before replacing their generated bytes.
- Authored sources and generated outputs have explicit roles; the generated home
  compatibility page is a documented exception, not an authoring template.
  Old research URLs/anchors stay usable; new builds do not require writing there.
- Validate all required inputs before publication. Saved-source fallback is
  explicit, hash-verified and visibly labeled; missing or changed snapshots fail.
  Failure leaves current working entry pages/edition intact.
- Build/verify/search checks accept the selected edition, preserve manifest
  source/output/original hashes and remain wired to the root test inventory.
  Migration docs describe required local evidence and portable bundle contents.

## Validation

Build to a temporary fresh edition with the existing research input, run link,
anchor, catalog, hash and Node search checks, and compare a before/after input
manifest. Exercise missing canonical source and corrupt saved snapshot failures.
Check Overview → Installation → Quick Start → Experiments → Supporting records,
basic entry and compatibility home in available browser preview. Record direct-file
rendering separately; HTTP/static success does not prove file-open success.
