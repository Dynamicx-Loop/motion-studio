# 07 — Relocate one artifact cohort with verified legacy compatibility

Status: ready-for-agent
Category: enhancement

## Context

The HiPHI robot-control experiment contains two 94,642,997-byte checkpoints,
generated motion/geometry and a local viewer alongside reproduction code and
small results. Its README documents exact run/export commands and viewer paths.
This is a bounded pilot for the larger storage cleanup, not permission to remove
experimental evidence or rerun expensive jobs.

## Outcome and scope

Implement a Motion Studio-owned relocation/verification operation with a thin
command and dry-run plan, then use it on the inventoried generated artifacts of
experiments/hiphi-robot-control. Keep source/configs/small results and frozen
records where they are. Place generated bytes in a fresh ignored output archive
and preserve the viewer and historical readers through explicit path mappings.

## Acceptance criteria

- Dry-run enumerates source/destination, role, size/hash, inbound links and exact
  compatibility action; no blanket extension-based or directory-wide move.
  Include referenced robot/model/mesh closure without redistributing source assets.
- Copy first, independently verify hashes and references, then install recorded
  aliases where safe. Refuse source drift, destination collision, unsafe symlink
  traversal or an unverified alias. Interrupted work retains readable originals
  and resumable verified copies. Do not clobber unrelated output directories.
- Additive relocation manifest preserves original path/hash plus new path,
  compatibility type and checks. Historical reports/configs/hashes stay unchanged.
  Keep unsafe-to-alias originals with an explicit reason; do not claim relocation.
- Existing viewer URLs, synchronized robot/source controls, motion paths and
  referenced JSON/bin/mesh resources still resolve. Existing reproduction/export
  tools remain preserved; document a fresh-run route and protect frozen archives
  from a command that would overwrite an alias target.
- Output storage/ignore policy excludes new bulky generated data without hiding
  source, small provenance, tickets or patches. Restore procedure is documented
  and tested without deleting the sole copy of any artifact.

## Validation

Use independent manifests to compare bytes through old and new paths. Test tiny
fixtures for hash drift, conflicts, interruption/resume, relative links, nested
assets and rollback. Audit the pilot viewer's resource graph and run its saved
motion playback smoke check if browser access is available. Do not rerun training
or export over the frozen cohort. Recheck ticket 01's protected inputs/status and
record actual migrated bytes, compatibility checks and retained exceptions.

## Comments

Planning only. The pilot expands supported locations before migrating consumers;
compatibility removal is not part of this ticket.
