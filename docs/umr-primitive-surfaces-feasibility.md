# Astro primitive surfaces for UMR: feasibility and experiment

Research date: 2026-10-22. UMR checkout: `d1cdaedaf67a827198da71c5fa831f48b2e51f91` ([upstream](https://github.com/hanyang9/UMR/tree/d1cdaedaf67a827198da71c5fa831f48b2e51f91)). Investigated using the Matt Pocock research skill, primary source code, official MuJoCo documentation retrieved through Context7, and disposable CPU checks. No production code, configuration, MJCF, packages, or retargeting outputs were changed. No training or retargeting was started.

## Decision

**Yes: Astro's collision primitives can supply the robot surface while the human remains SMPL-X.** UMR already triangulates primitives and can bind surface slots to them. This does not require matching primitive decompositions on the human, or a new correspondence-learning method. However, **this is not a supported JSON-only switch in the current checkout**, and the existing coarse primitive path has sampling and binding defects worth addressing before judging accuracy.

Recommend an isolated A/B experiment, keeping the canonical MJCF and its physical collision model intact. Start with surface/binding validation, then train fresh correspondences for each surface. Do not assume simpler collision shapes improve motion quality or materially accelerate the per-frame solver. The paper establishes exterior surface correspondence across morphologies; it does not establish this specific Astro collision-proxy ablation. ([UMR paper](https://arxiv.org/html/2609.02134v2), [primitive adapter](../externals/UMR/scripts/mujoco_geom_surface.py), [binding](../externals/UMR/scripts/retarget_smpl_to_humanoid_surface_vector.py))

## What the code actually selects

`scripts/mujoco_geom_surface.py:21–71` is shared by dataset sampling and robot slot binding:

| Policy | Actual behavior |
| --- | --- |
| `auto` | Prefer mesh geoms with both contact masks zero and group other than 3, excluding floor-like names/world/planes; otherwise other non-floor meshes, then any meshes. |
| `visual` | Prefer those non-colliding, non-group-3 meshes, with fallback to all meshes. This branch does not apply floor removal. |
| `all_mesh` | All mesh geoms. |
| `mesh_no_floor` | Non-floor mesh geoms, with fallback to all meshes. |
| Primitive fallback | Only when the mesh selection is empty: spheres, capsules, ellipsoids, cylinders and boxes, excluding floor-like geoms. No group or contact-mask filter. |

Unknown strings silently follow the auto behavior. Setting `visual_geom_policy` to `collision`, `group3`, or a similarly invented value **does not** select collisions. Group 1 itself is not the criterion for a visual mesh.

There is also a wiring gap: `build_correspondence_ae_dataset.py:1126–1254` calls `surface_geom_ids(model)` without a policy, and `humanoid_retarget_pipeline.py:827–846` does not pass `robot.visual_geom_policy` into dataset building. Retarget binding does read it at `retarget_smpl_to_humanoid_surface_vector.py:680` and in the batch equivalent. A selector change must reach **both stages**, otherwise training and binding can use different surfaces. ([selector](../externals/UMR/scripts/mujoco_geom_surface.py), [dataset](../externals/UMR/scripts/build_correspondence_ae_dataset.py), [pipeline](../externals/UMR/scripts/humanoid_retarget_pipeline.py), [retarget binding](../externals/UMR/scripts/retarget_smpl_to_humanoid_surface_vector.py))

The 55 group-3 shapes comprise **39 capsules, 11 cylinders, 3 spheres and 2 boxes**, on 19 bodies. Each foot alone has 8 capsules, 2 cylinders and a box. Fewer directly represented bodies does not automatically mean missing joints: some geoms belong to welded child/parent bodies, while other primitive volumes intentionally approximate several visual pieces. Nevertheless, slots inherit their selected geom's actual kinematics, so inspect bindings near shoulders, hip yaw, knees, wrists, and feet. Geometry proximity alone can attach a point to the wrong moving body. ## Primitive support is triangulated, not analytic surface sampling

`geom_local_mesh` at `mujoco_geom_surface.py:172` directly supports all five primitive types. It creates local triangle meshes (24 angular segments; sphere 12 latitude intervals; capsule 8 intervals per hemisphere), transforms them using compiled geom poses, and concatenates their faces. Dataset sampling is area-weighted triangle sampling, optional exterior filtering, then farthest-point sampling. No external mesh export is required. MuJoCo primitive sizes and compiled orientations already account for `fromto`; capsules/cylinders use radius plus half-length, boxes use half-extents. ([UMR adapter](../externals/UMR/scripts/mujoco_geom_surface.py), [sampler, lines 346–416](../externals/UMR/scripts/build_correspondence_ae_dataset.py), [official MuJoCo geom documentation](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-geom))

The shared binding code still expects triangles. It projects reconstructed slots onto selected triangles, recovers each face's geom ID, and stores geom-local positions and normals. Later forward kinematics uses those fixed local bindings; it does not require an original mesh asset. `project_robot_slots=false` only keeps the unprojected point after finding a face: it still requires triangle binding for ownership and normals, and does not solve incorrect owner selection. ([binding, lines 627–712](../externals/UMR/scripts/retarget_smpl_to_humanoid_surface_vector.py), [projection and motion, lines 711–793](../externals/UMR/scripts/smpl_surface_retarget_common.py))

### Confirmed issues from small CPU checks

All checks used `externals/UMR/.venv/bin/python`, the configured T-pose, and in-memory overrides only. Disposable reproduction script: `/tmp/umr_primitive_surface_probe.py`; it imports the existing sampler and binder, selects only group-3 supported primitives, and starts no optimizer.

1. **Overlapping/interior surfaces are significant.** Of 20,000 area-weighted triangle samples (NumPy RNG seed 0), **6,672 (33.36%)** were strictly inside another analytic primitive using a 10-micrometer tolerance. 6,067 were inside a primitive on the same body; 613 inside one on a different body; these categories overlap. Existing `first_hit` exterior filtering plus FPS (512 slots, seed 9000, oversample 8) reduced this to **24/512 (4.69%)**, including 21 same-body and 3 other-body cases. This is a sample diagnostic, not an estimate of final trained-slot quality.

   The reason is visible in code: `exterior_first_hit_mask` evaluates visibility at **triangle centroids**, using 26 directions and requiring two first hits, then applies that face-level decision to every candidate on the face. A partly exposed large triangle can retain buried points elsewhere on it. It is not an exact Boolean union or pointwise inside-volume test. Preserve the existing exterior filter and consider an additional pointwise primitive-union rejection step; do not simply concatenate all collision surfaces without filtering. ([exterior filter, lines 475–537](../externals/UMR/scripts/build_correspondence_ae_dataset.py))

2. **Nearest-vertex candidate binding is unreliable on this coarse surface.** Rebinding those same 512 sampled points, which already lie on triangles, should require essentially zero displacement. With default `nearest_vertex_k=24`, mean/p95/max displacement was **0.784/1.707/33.070 mm**; 27 points shifted over 1 mm and 6 were assigned to a different body than the sampled face. Raising `k` to 96 gave a 17.131 mm maximum; `k=256` still gave a 17.131 mm maximum and two different-body assignments. The function searches only faces incident to the nearest vertices, so it can miss a nearby large triangle whose vertices are distant. These are projection-candidate errors, separate from correspondence-learning error. Use a robust nearest-triangle search, suitably refined triangles with validation, or a validated analytic primitive projector that also returns geom ownership. Increasing `k` alone was not sufficient in this check. ([candidate search, lines 711–759](../externals/UMR/scripts/smpl_surface_retarget_common.py))

3. **Primitive triangle winding is inconsistent.** A cross-product-normal dot face-centroid check on centered convex primitives found every nondegenerate sphere/capsule face inward, cylinder side faces inward but caps outward, and boxes outward. `_connect_rings` emits reversed winding. Correcting its winding addresses sphere, ellipsoid, capsule and cylinder side orientation without reversing already-correct caps/boxes. Zero-area pole triangles should also be removed or excluded from binding; sampling already excludes them.

   This is **not evidence that the current default orientation objective must fail**: `surface_normal_cost_mode='tpose_offset'` transports the robot's own reference normal through the human bound face. A fixed per-slot sign reversal flips both the current and target normals, leaving the squared residual unchanged. It matters for direct source-normal matching, outward-normal interpretation, and future normal-sensitive algorithms. Existing first-hit visibility does not use the candidate normals, and normal-occlusion tests both directions. ([ring triangulation, lines 86–133](../externals/UMR/scripts/mujoco_geom_surface.py), [normal target transport, lines 2609–2673](../externals/UMR/scripts/retarget_smpl_to_humanoid_surface_vector.py))

The binding smoke check did complete with finite positions and only group-3 geom IDs. This verifies mechanical compatibility, not good bindings, learned correspondence, motion accuracy, or speed. The 512-point exterior sampler took about 0.30 seconds locally; this was not a controlled visual-versus-primitive performance benchmark.

## Labels, contact constraints, and physical collisions

The correspondence learner consumes ordered/unordered point clouds, template geometry, and geometric losses; it does not learn from Astro geom group numbers or a supplied robot body-part map. Later, source surface binding supplies SMPL-X body-part labels; the shared slot ordering transfers those labels and region weights to robot slots. Geom/body IDs determine how robot slots move and how their Jacobians are computed. Thus **SMPL-X can remain unchanged**. Replacing it with primitives would be a separate experiment that also changes source geometry and contact evidence. ([training dataset and losses](../externals/UMR/scripts/train_correspondence_template_residual_ae.py), [source binding and part IDs, lines 2294–2490](../externals/UMR/scripts/retarget_smpl_to_humanoid_surface_vector.py), [paper sections III-B/C](https://arxiv.org/html/2609.02134v2))

Ground/contact-map objectives operate on the bound robot points. The default hard ground constraint uses `surface_slots_all`, so a surface replacement changes the points constrained against the floor. Finite sampled points still do not guarantee that the entire analytic collision model clears the floor. `mujoco_collision` is a separate ground-constraint mode. Self-penetration and robot-object penetration paths select collision-enabled geoms using contact masks and perform geom-distance computations; these do not need a visual triangle mesh. An external object's point-cloud loader has its own mesh-selection logic; robot primitive support should not be generalized into a claim that every object-loading path accepts primitive-only objects. ([ground modes, lines 2030–2070](../externals/UMR/scripts/retarget_smpl_to_humanoid_surface_vector.py), [collision caches, lines 1029–1124](../externals/UMR/scripts/smpl_surface_retarget_common.py), [object loader and collision selection, lines 1052–1063 and 1357–1371](../externals/UMR/scripts/retarget_smpl_to_humanoid_surface_vector.py))

**Changing the sampling selector does not change physical collisions.** MuJoCo uses contact bitmasks and other collision filters; `group` is primarily a visualization/custom-computation tag and can affect inertia inference when enabled. Astro explicitly uses `inertiafromgeom='false'` and explicit inertials. Keep the original model's shapes, masks, mass, inertia and joint structure intact. Do not enable collisions on the visual meshes just to select a surface. ([official MuJoCo group/geom documentation](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-geom), [official collision filtering](https://mujoco.readthedocs.io/en/stable/computation/index.html#collision-detection), [Astro compiler and inertials](/data/workspace/notAnyrobot/menagerie_x/robots/astro_p2_29dof/astro_p2_29dof.xml))

## Minimal integration and controlled comparison

There is **no existing config-only value** for this. The smallest clean integration into the canonical model would be:

1. Add an explicit `collision_primitives` branch to the shared `surface_geom_ids`: supported primitive type, non-floor, `geom_group == 3`, and nonzero `contype` or `conaffinity`; fail if empty. Keep existing behavior unchanged otherwise. Group 3 is Astro's convention, not a universal MuJoCo collision requirement.
2. Thread `visual_geom_policy` through `visual_mesh_geom_ids`, `robot_visual_mesh_in_root_frame`, `build_robot_sample`, and the pipeline's dataset call. Retarget/batch binding already passes the config key to the shared selector. Verify all active entry points use the same selected geom list.
3. In an isolated copy of Astro's config, set the **newly implemented** `robot.visual_geom_policy` to `collision_primitives`; keep `robot.xml` canonical and retain the T-pose. Use separate `correspondence.dataset.out`, `correspondence.train.out_dir`, and retarget output paths; leave `correspondence.slots=null` to derive a fresh slots file. Current compatibility checks mainly inspect names/training mode, not surface selection, so old caches can otherwise be silently reused. A durable implementation should record/check surface policy and geometry fingerprints. ([cache paths and compatibility, lines 319–462](../externals/UMR/scripts/humanoid_retarget_pipeline.py))
4. Before scoring quality, correct primitive winding and validate/refine projection and interior rejection. Apply these only in a separate experimental checkout or reviewed patch, not silently during another running job.

A code-free fallback is a derived MJCF with all visual mesh geoms and the two visual hand spheres removed, preserving explicit inertials, joints, bodies and all 55 collision primitives: existing `auto` then falls back to primitives. This still has the triangulation/binding issues above, changes geom numbering and visualization, and needs separate output metadata. It is less suitable than a selector patch for comparing results while rendering the original robot.

Proposed experiment:

- **A: current visual surface. B: cleaned exterior of the same group-3 primitive surface.** Keep the exact same SMPL-X template/betas, human sampled cloud, completed T-pose, random seeds, 4,096-point budget, learning schedule, solver weights and physical collision model. Do not compare an old visual correspondence against newly rebound primitive slots: rebuild/train each robot correspondence separately. Defer a visual-hands-inclusive control or hybrid hand/foot surface until the first comparison identifies a reason.
- **Geometry gate before training:** inspect region coverage and geom/body ownership, report interior-sample rates before and after filtering, verify outward normals, and rebind points sampled exactly on each candidate surface. Require negligible identity-rebinding error and explain every changed body owner. Keep the human cloud fixed so different source sampling does not confound the comparison.
- **Correspondence gate:** compare multiple fixed seeds for coverage, per-region reconstruction/projection error, left/right swaps and cross-joint assignments. Chamfer loss alone cannot establish semantic quality. Symmetric capsules/spheres may reduce distinctive cues and make twist/left-right ambiguities worse; this is a hypothesis, not a measured result.
- **Only after those gates:** use short existing, independently named clips with walking/standing, arm rotation, and a contact-rich action. Measure foot slip, ground/collision penetration on the unchanged physical model, joint-limit violations, source-to-robot surface/contact residuals, wrist/foot orientation, and visible motion. Evaluate final robot visual geometry too: a collision proxy can place contacts consistently with physics while producing a visibly incorrect clearance to the shell.
- **Time the stages separately:** sampling, binding, training, and per-frame solve. The triangle reduction is about 11.4×; it can reduce geometry preprocessing. The same point budget, network and robot DOFs do not imply an 11.4× training or solver speedup. Report wall time and memory rather than extrapolating from triangle count. ([triangle-based preprocessing](../externals/UMR/scripts/build_correspondence_ae_dataset.py), [point-cloud learner](../externals/UMR/scripts/train_correspondence_template_residual_ae.py), [slot-based solver](../externals/UMR/scripts/retarget_smpl_to_humanoid_surface_vector.py))

Expected tradeoff, still untested: primitives can suppress shell details and align fitting contacts with the collision envelope, while losing palm/sole detail, changing local radii and kinematic attachment, and providing weaker rotational cues. Prefer the proxy only if measured contact/pose quality meets the visual baseline and its preprocessing or consistency benefits justify the added adapter work. No claim of superior Astro retargeting quality follows from the smoke checks alone.
